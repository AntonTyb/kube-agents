## 1. Executive Summary

This proposal outlines the technical strategy for hardening the GKE Platform Agent GitOps workflow, token refresh mechanisms, and deployment CI pipelines. The proposal addresses four identified security findings (PIPE-004, SKILL-006, SEC-004, SEC-005):

1. **Eliminating Force-Pushing (`git push -f`):** Transitioning `submit_suggestion.py` to non-force pushing to prevent accidental remote history rewrites and protect git tree integrity.
2. **Mandatory OIDC Audience Validation:** Enforcing `--audiences` parameters in `github_token_refresh.py` during Google OIDC identity token generation and removing the un-audiented fallback mechanism.
3. **Secure Secrets Handling in CI:** Eliminating hardcoded global `/tmp/` paths for GitHub App private key PEM files during integration redeploy workflows and moving them to job-isolated runner temporary paths (`${{ runner.temp }}`) with guaranteed cleanup.

## 2. Problem Analysis & Findings

### Finding 1: Insecure Force-Push in PR Submitter (PIPE-004 / SKILL-006)
- **Location:** `agents/platform/skills/submit-suggestion/scripts/submit_suggestion.py` (Line 26)
- **Current Code:**
  ```python
  subprocess.run(["git", "push", "-f", "origin", branch_name], check=True)
  ```
- **Vulnerability / Risk:** Using `git push -f` force-pushes changes to the remote repository. If an agent reuses a branch or targets a ref improperly, force-pushing overwrites existing remote history without checks, creating risk of history corruption or bypassing git protection semantics.

### Finding 2: Un-audiented OIDC Token Fallback (SEC-004 / SEC-005)
- **Location:** `agents/platform/scripts/github_token_refresh.py` (Lines 80–88)
- **Current Code:**
  ```python
  try:
      oidc_token = subprocess.run(
          ["gcloud", "auth", "print-identity-token", f"--audiences={TOKEN_BROKER_URL}"],
          ...
      ).stdout.strip()
  except Exception as e1:
      # If --audiences fails (e.g., when running with human user credentials), retry without flags
      try:
          oidc_token = subprocess.run(
              ["gcloud", "auth", "print-identity-token"],
              ...
          ).stdout.strip()
      except Exception as e2:
          raise RuntimeError(...)
  ```
- **Vulnerability / Risk:** Minty (the GitHub Token Minter) validates OIDC tokens against target audience claims (`TOKEN_BROKER_URL`) to prevent token replay and cross-service token misuse. If the primary call fails, falling back to an un-audiented `gcloud auth print-identity-token` generates a default-audience token. Transmitting un-audiented tokens degrades zero-trust identity boundaries and enables token replay risks.

### Finding 3: Insecure PEM File Storage in Shared `/tmp` (PIPE-004 / SEC-004)
- **Location:** `.github/workflows/staging-redeploy-integrations.yml` and `.github/workflows/reusable-deploy-integrations.yml` (Lines 225, 258–259)
- **Current Code:**
  ```yaml
  env:
    GITHUB_PEM_PATH: "/tmp/github_app_pem_path"
  ...
  - name: Create GitHub Private Key PEM File
    run: |
      if [ -n "$PEM_SECRET" ]; then
        echo "$PEM_SECRET" > "$GITHUB_PEM_PATH"
        chmod 600 "$GITHUB_PEM_PATH"
      fi
  ```
- **Vulnerability / Risk:** Writing unencrypted private key PEM files to a shared global directory (`/tmp/github_app_pem_path`) exposes sensitive credentials to other processes running on the host or shared runner environment. Furthermore, `/tmp` files may persist across workflow steps or job boundaries if not explicitly purged.

## 3. Proposed Architecture & Implementation Plan

### 3.1. Non-Force Branch Pushing in `submit_suggestion.py`

Modify `push_branch()` in `agents/platform/skills/submit-suggestion/scripts/submit_suggestion.py` to remove `-f`:

```python
def push_branch(branch_name: str):
    """Push the active git branch to the remote origin securely."""
    protected_branches = {"main", "master", "production"}
    clean_branch = branch_name.strip().lower()
    if clean_branch in protected_branches:
        raise ValueError(f"CRITICAL SECURITY REFUSAL: Branch '{branch_name}' is strictly blocked by GKE SRE guardrails!")

    log(f"Pushing active branch '{branch_name}' securely to origin...")
    subprocess.run(["git", "push", "origin", branch_name], check=True)
```

- **Behavior:** Standard `git push origin branch_name` will fail gracefully if remote branch history has diverged, requiring proper branch management rather than force-overwriting.

### 3.2. Mandatory OIDC Audience Validation in `github_token_refresh.py`

Refactor `refresh_git_credentials()` in `agents/platform/scripts/github_token_refresh.py` to enforce `--audiences` and remove the un-audiented fallback:

```python
    # 1. Retrieve Google OIDC identity token via gcloud with mandatory audience validation
    try:
        oidc_token = subprocess.run(
            ["gcloud", "auth", "print-identity-token", f"--audiences={TOKEN_BROKER_URL}"],
            capture_output=True, text=True, check=True,
            timeout=10
        ).stdout.strip()
    except Exception as e:
        raise RuntimeError(
            f"Failed to retrieve audience-restricted Google OIDC token (--audiences={TOKEN_BROKER_URL}): {e}"
        ) from e
```

- **Behavior:** Ensures all OIDC tokens generated via `gcloud` explicitly specify `TOKEN_BROKER_URL` as audience. Token minting requests failing audience restrictions will abort immediately rather than issuing insecure fallback tokens.

### 3.3. Isolation & Cleanup of Private Key PEM Files in GitHub Workflows

Update `.github/workflows/reusable-deploy-integrations.yml` (referenced by `staging-redeploy-integrations.yml`):

1. Update `GITHUB_PEM_PATH` environment variable definition to use `${{ runner.temp }}`:
   ```yaml
   env:
     GITHUB_PEM_PATH: "${{ runner.temp }}/github_app_pem_path"
     NAMESPACE: "kubeagents-system"
   ```
2. Add explicit cleanup step post-deployment using `always()` condition:
   ```yaml
   - name: Perform GitHub Token Minter Redeployment
     ...

   - name: Securely Clean Up Private Key PEM File
     if: always()
     run: |
       if [ -f "${{ env.GITHUB_PEM_PATH }}" ]; then
         shred -u "${{ env.GITHUB_PEM_PATH }}" 2>/dev/null || rm -f "${{ env.GITHUB_PEM_PATH }}"
         echo "Cleaned up GitHub private key PEM file."
       fi
   ```

## 4. Code Comment Conflicts & Architectural Questions

During codebase inspection, a specific code comment conflict was identified:

### ⚠️ Conflict in `github_token_refresh.py` (Line 80)
- **Existing Comment:**
  ```python
  # If --audiences fails (e.g., when running with human user credentials), retry without flags
  ```
- **Nature of Conflict:** The code comment explicitly documents that the fallback to `gcloud auth print-identity-token` without `--audiences` was intentional to support local testing by human developers using personal GCP user accounts (where `gcloud` might fail to generate audience-restricted identity tokens for third-party client IDs).
- **Security Impact of Resolution:** Removing the fallback strictly enforces zero-trust token audience scoping required by Minty, but may break local developer invocation of `github_token_refresh.py` if human user credentials cannot issue `--audiences` tokens.

### ❓ Open Questions for SRE / Security Team
1. **Human Developer Authentication Support:** Should human local development bypass Minty via `CREDENTIAL_PROXY_URL` or local mock credentials, rather than attempting direct un-audiented OIDC token exchanges with Minty?
2. **GCP User Account Permissions:** Has Minty been configured to accept user identity tokens with explicit `--audiences` set to the cluster token broker service account / URL, eliminating the need for un-audiented user tokens?

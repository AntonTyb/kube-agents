## 1. Executive Summary & Problem Statement

The `PlatformAgent` Custom Resource Definition (CRD) in `kube-agents` defines the desired state, harness infrastructure, and security posture of platform AI agents running in Kubernetes. Currently, `PlatformAgentSpec.Deployment` allows flexible customization of compute resources, including `initContainers`, `sidecars`, environment variables (`env`), extra volume mounts (`sidecarVolumes`, `extraVolumes`), and runtime classes (`RuntimeClassName`).

While flexible, the existing validating admission webhook (`PlatformAgentCustomValidator` in `k8s-operator/internal/webhook/platformagent_webhook.go`) only enforces a single cluster-level invariant: **one `PlatformAgent` per project**. It does not inspect container security contexts, environment variable overrides, volume sources, or sandbox runtime configurations.

Without API-boundary admission control validation, a user or automated system with `PlatformAgent` CRD write access (or an attacker exploiting prompt injection to generate a CRD manifest) could craft a payload that:

- Elevates pod execution privileges to root or injects privileged containers (**ADM-001**, **ADM-002**).
- Overrides critical internal security sentinels or tokens such as `API_SERVER_KEY` (**ADM-003**).
- Mounts host filesystems via `hostPath` volumes to escape the pod sandbox (**ADM-004**).
- Bypasses sandboxed runtime isolation (**ARCH-003**).
- Escapes container isolation to achieve lateral movement (**THREAT-004**, **PI-003**).

This design proposal extends `PlatformAgentCustomValidator` to enforce comprehensive security bounds on all `PlatformAgent` specs at the Kubernetes API boundary, while addressing architectural considerations around resource deletion and lock release.

## 3. Detailed Technical Design & Specifications

### 3.1 Architecture Overview

We will extend `PlatformAgentCustomValidator.validatePlatformAgent(ctx, platformAgent)` in `k8s-operator/internal/webhook/platformagent_webhook.go` by invoking structured validation helpers:

```go
func (v *PlatformAgentCustomValidator) validatePlatformAgent(ctx context.Context, platformAgent *agentv1alpha1.PlatformAgent) (admission.Warnings, error) {
    // Skip validation for terminating agents to avoid deadlocks during deletion (e.g. finalizer removal)
    if platformAgent.DeletionTimestamp != nil {
        return nil, nil
    }

    var allErrs field.ErrorList

    // 1. Enforce 1 PlatformAgent per project limit
    if err := v.validateSingleAgentPerProject(ctx, platformAgent); err != nil {
        return nil, err
    }

    // 2. Enforce compute security bounds
    if platformAgent.Spec.Deployment != nil {
        allErrs = append(allErrs, validateInitContainers(platformAgent.Spec.Deployment.InitContainers, field.NewPath("spec", "deployment", "initContainers"))...)
        allErrs = append(allErrs, validateSidecars(platformAgent.Spec.Deployment.Sidecars, field.NewPath("spec", "deployment", "sidecars"))...)
        allErrs = append(allErrs, validateEnvOverrides(platformAgent.Spec.Deployment.Env, field.NewPath("spec", "deployment", "env"))...)
        allErrs = append(allErrs, validateVolumes(platformAgent.Spec.Deployment.SidecarVolumes, field.NewPath("spec", "deployment", "sidecarVolumes"))...)
        allErrs = append(allErrs, validateVolumes(platformAgent.Spec.Deployment.ExtraVolumes, field.NewPath("spec", "deployment", "extraVolumes"))...)
        if platformAgent.Spec.Deployment.Availability != nil {
            allErrs = append(allErrs, validateRuntimeClassName(platformAgent.Spec.Deployment.Availability.RuntimeClassName, field.NewPath("spec", "deployment", "availability", "runtimeClassName"))...)
        }
    }

    if len(allErrs) > 0 {
        return nil, apierrors.NewInvalid(
            schema.GroupKind{Group: "kubeagents.x-k8s.io", Kind: "PlatformAgent"},
            platformAgent.Name,
            allErrs,
        )
    }

    return nil, nil
}
```

### 3.2 `InitContainers` and `Sidecars` Security Bounds (**ADM-001**, **ADM-002**)

For every container in `spec.deployment.initContainers` and `spec.deployment.sidecars`, the webhook enforces:

1. **No Privileged Execution:**
   - If `container.SecurityContext != nil && container.SecurityContext.Privileged != nil && *container.SecurityContext.Privileged == true`, reject with `field.Forbidden`.
2. **Non-Root User / UID Constraint:**
   - If `container.SecurityContext != nil && container.SecurityContext.RunAsUser != nil && *container.SecurityContext.RunAsUser == 0`, reject with `field.Forbidden` ("root execution is forbidden").
3. **Restricted Linux Capabilities:**
   - Deny containers requesting dangerous capabilities in `SecurityContext.Capabilities.Add`:
     - `"CAP_SYS_ADMIN"`, `"CAP_NET_ADMIN"`, `"CAP_SYS_PTRACE"`, `"CAP_SYS_MODULE"`, `"CAP_SYS_BOOT"`, `"ALL"`.
4. **Reserved Port Protection (`Sidecars` only):**
   - Sidecars must not bind to reserved operator container ports:
     - `8699` (`event-watcher` daemon URL)
     - `8888` / `8889` (credential proxy endpoints)

---

### 3.3 `Env` Overrides Blocklist (**ADM-003**)

To prevent users from hijacking internal agent authentication, overriding loopback sentinels, or injecting dynamic linkers, the webhook enforces a strict deny-list on `spec.deployment.env[].name`:

#### Reserved Environment Variables (Blocklist):

- **Authentication & Sentinels:**  
  `API_SERVER_KEY`, `API_SERVER_HOST`, `SESSION_KV_DB_PATH`
- **Credential Proxy Configuration:**  
  `CREDENTIAL_PROXY_BOOTSTRAP_COMMAND`, `CREDENTIAL_PROXY_POLICY`, `CREDENTIAL_PROXY_UNIX_SOCKET`, `CREDENTIAL_PROXY_PORT`, `CREDENTIAL_PROXY_WORKSPACE_ROOT`, `CREDENTIAL_PROXY_MAX_OUTPUT_BYTES`, `CREDENTIAL_PROXY_MAX_REQUEST_BYTES`, `CREDENTIAL_PROXY_STATE_DIR`, `CREDENTIAL_PROXY_TIMEOUT_SECONDS`, `KSA_TOKEN_FILE`, `TOKEN_BROKER_URL`
- **Sensitive Identity & Secrets:**  
  `GKE_PROJECT_ID`, `GKE_CLUSTER_NAME`, `GKE_LOCATION`, `KUBE_CONTEXT_NAME`, `SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN`, `GOOGLE_CHAT_PROJECT_ID`, `GOOGLE_CHAT_SUBSCRIPTION_NAME`
- **Loader & Dynamic Execution Injection:**  
  `LD_PRELOAD`, `LD_LIBRARY_PATH`, `PYTHONPATH`, `PATH`, `BASH_ENV`, `ENV`

If any variable in `spec.deployment.env` matches the blocklist, the webhook returns:

```
field.Forbidden(path, fmt.Sprintf("environment variable '%s' is reserved by the operator and cannot be overridden", env.Name))
```

---

### 3.4 Volume Source Validation (**ADM-004**)

To prevent container escape and node filesystem traversal, `validateVolumes` inspects all volumes in `sidecarVolumes` and `extraVolumes`:

1. **Prohibit HostPath Volumes:**
   - If `vol.HostPath != nil`, reject with `field.Forbidden(path, "HostPath volumes are forbidden for security reasons")`.
2. **Allowlist Safe Volume Types:**
   - Allow only: `ConfigMap`, `Secret`, `EmptyDir`, `PersistentVolumeClaim`, `Projected`, `DownwardAPI`.
   - Deny all other volume sources (e.g., raw CSI drivers without explicit operator provisioning, NFS, host mounts).

---

### 3.5 `RuntimeClassName` Validation (**ARCH-003**)

When agents execute untrusted LLM-generated code or workflows, kernel-level isolation is required:

1. **Allowed Runtime Classes:**
   - The webhook validates `Spec.Deployment.Availability.RuntimeClassName` against secure sandbox runtimes: `"gvisor"` or `"kata"` (as well as standard `"gce-sandbox"` if deployed on GKE).
2. **Defaulting Policy:**
   - In `PlatformAgentCustomDefaulter.Default(ctx, obj)` (`k8s-operator/internal/webhook/platformagent_webhook.go:59`), if `Spec.Deployment != nil` and `Spec.Deployment.Availability == nil`, or `Spec.Deployment.Availability.RuntimeClassName == nil`, default `RuntimeClassName` to `"gvisor"`.

## 4. Architectural Conflict & Open Question: Deletion Lifecycle (`ValidateDelete` and GCS Lock Release)

### 4.1 Statement of Conflict

The task description instructs:

> _"Implement proper GCS lock release and `ValidateDelete` stubs."_

However, implementing GCS (Google Cloud Storage) lock/lease release inside `ValidateDelete` or blocking deletion in `ValidateDelete` **violates Kubernetes Admission Control semantics and conflicts with explicit design comments in the codebase**.

#### 1. Direct Conflict with Code Comments

In `k8s-operator/internal/webhook/platformagent_webhook.go:103`, the existing codebase contains an explicit comment and deadlock-prevention guard:

```go
// Skip validation for terminating agents to avoid deadlocks during deletion (e.g. finalizer removal)
if platformAgent.DeletionTimestamp != nil {
    return nil, nil
}
```

Furthermore, `k8s-operator/internal/webhook/platformagent_webhook_test.go:121` explicitly tests:

```go
t.Run("allows update when the agent under validation is terminating to prevent deadlocks", ...)
```

#### 2. Conflict with Webhook Side-Effect Contracts (`sideEffects=None`)

In `k8s-operator/internal/webhook/platformagent_webhook.go:71`, the kubebuilder annotation declares:

```go
// +kubebuilder:webhook:...,sideEffects=None,verbs=create;update;delete,...
```

By Kubernetes API specification, a validating admission webhook (`ValidatingWebhookConfiguration`) MUST be pure, idempotent, and **side-effect-free** (`sideEffects=None`). A validating webhook must never perform external mutations, delete network resources, or release distributed locks in Google Cloud Storage (GCS).

#### 3. Architectural Separation of Concerns (Webhook vs. Controller Finalizer)

In Kubernetes operator design:

- **Validating Admission Webhooks (`ValidateDelete`)** are synchronous API-server guards. If a webhook attempts to call an external API (such as GCS) to release a lock and that service is temporarily slow or unreachable, deletion requests will time out or deadlock, leaving resources permanently stuck in `Terminating`.
- **Controller Finalizers (`PlatformAgentReconciler.handleDeletion` in `platformagent_controller.go`)** are asynchronous reconcilers responsible for cleanup and releasing external resources before removing finalizers. Currently, `handleDeletion` (`platformagent_controller.go:168`) removes ClusterRoleBindings, Roles, and RoleBindings before removing `platformAgentFinalizer` (`"kubeagents.x-k8s.io/finalizer"`).

---

### 4.2 Explicit Design Question for Reviewers

**Question:**  
Should GCS lock/lease release be implemented inside the **Controller Finalizer** (`PlatformAgentReconciler.handleDeletion` in `k8s-operator/internal/controller/platformagent_controller.go`) when cleaning up external resources, while keeping `ValidateDelete` in `platformagent_webhook.go` as a non-blocking, side-effect-free stub (`return nil, nil`) that honors the deadlock-prevention comment at line 103?

### 4.3 Recommended Resolution

We recommend:

1. **In `platformagent_webhook.go` (`ValidateDelete`)**: Keep `ValidateDelete` as a side-effect-free stub (`return nil, nil`) that logs deletion intent but performs no blocking external calls or lock releases, preserving compliance with `sideEffects=None` and `platformagent_webhook.go:103`.
2. **In `platformagent_controller.go` (`handleDeletion`)**: Implement GCS distributed lock / lease release logic within `handleDeletion(ctx, agent)` immediately prior to `controllerutil.RemoveFinalizer(agent, platformAgentFinalizer)`. This ensures reliable, retryable cleanup without risking API-server deletion deadlocks.

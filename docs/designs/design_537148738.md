# Design Proposal: Buganizer Task 537148738 — CI/CD Pipeline Security Scanning & Dependency Management

**Task Reference:** Buganizer Task 537148738
**Author:** Platform Engineering & Security Team
**Status:** Implemented (Design of Record)
**Target Files:** `.github/workflows/*`, `.github/dependabot.yml`
**Findings Included:** PIPE-001, PIPE-002, PIPE-003, PIPE-005, PIPE-006

---

## 1. Executive Summary

This technical design proposal establishes a comprehensive security hardening and automated governance framework for the `kube-agents` CI/CD infrastructure on GitHub Actions. By addressing findings PIPE-001, PIPE-002, PIPE-003, PIPE-005, and PIPE-006 (PIPE-004 is addressed separately), this design implements immutable action SHA pinning, safe output variable encapsulation, multi-layered static security analysis (`gosec`, `trivy`, `semgrep`, `checkov`), full-stack Dependabot ecosystem coverage (Go, Python, Node.js, Docker, Actions), and strict least-privilege workflow permissions.

---

## 2. Security Findings & Detailed Assessment

### 2.1 PIPE-001: Unpinned Third-Party GitHub Actions

- **Current State:** Workflows throughout `.github/workflows/` reference third-party GitHub Actions via floating branch or tag identifiers (e.g., `uses: actions/checkout@v7`, `uses: docker/build-push-action@v7`, `uses: actions/setup-go@v7`).
- **Security Risk:** Mutable tag references can be updated or overwritten upstream (either intentionally or via account compromise), introducing supply chain attack vectors or unexpected breaking changes into build pipelines.
- **Target Fix:** Pin every action invocation to an immutable 40-character git commit SHA, accompanied by an inline comment indicating the release tag (e.g., `uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`). Container images used in workflow jobs must similarly be pinned to explicit version tags and immutable SHA256 digests (e.g., `image: semgrep/semgrep:1.155.0@sha256:...`) rather than defaulting to mutable floating tags or `latest`.

### 2.2 PIPE-002: Insecure `$GITHUB_OUTPUT` Writes & Unverified Binary Downloads

- **Current State:**
  - In `docker-publish-gcp.yml` and `reusable-deploy-integrations.yml`, dynamic step outputs are written directly using single-line string concatenation (`echo "digest=$DIGEST" >> "$GITHUB_OUTPUT"`).
  - In `actionlint.yml`, binary dependencies are retrieved via unverified `curl -sSfL` downloads without hash verification.
- **Security Risk:**
  - Direct string concatenation without heredoc delimiters can lead to output truncation, multiline line-injection, or broken workflow evaluation if output strings contain spaces, newlines, or control characters.
  - Downloading unverified binaries via `curl` introduces remote code execution and supply chain risks.
- **Target Fix:** Standardize output writes to use safe heredoc delimiter syntax (`{ echo "key<<EOF"; echo "$VAL"; echo "EOF"; } >> "$GITHUB_OUTPUT"`) and replace raw `curl` scripts with official, pinned GitHub Actions (`rhysd/actionlint-action`).

### 2.3 PIPE-003: Missing Static Security Analysis Scanners

- **Current State:** CI pipelines lack automated static security scanners for Go source code, container images, Infrastructure-as-Code (Kubernetes manifests, Helm charts, Dockerfiles), and Python scripts.
- **Security Risk:** Vulnerabilities such as hardcoded credentials, permissive Kubernetes RBAC/Pod security policies, outdated container bases, or unsafe code patterns can bypass review into production.
- **Target Fix:** Implement a dedicated, multi-job `.github/workflows/security-scan.yml` incorporating `gosec` (Go SAST), `trivy` (container & manifest misconfiguration scan), `semgrep` (multi-language SAST), and `checkov` (IaC compliance).

### 2.4 PIPE-005: Incomplete Dependabot Ecosystem Coverage

- **Current State:** `.github/dependabot.yml` monitors only `github-actions` at the root and `docker` for subdirectories `/agents/platform`, `/agents/operator`, `/agents/devteam`. It lacks tracking for Go (`k8s-operator/go.mod`), Python (`tests/e2e/requirements.txt`), Node.js (`docs/site/package.json`), and additional Docker directories (`deploy/docker`).
- **Security Risk:** Outdated language packages and dependencies are left unmonitored for known CVEs.
- **Target Fix:** Expand `.github/dependabot.yml` to include `gomod`, `pip`, `npm`, and additional `docker` directory updates on a scheduled weekly cadence.

### 2.5 PIPE-006: Insecure Event Triggers & Permissive Permissions Hygiene

- **Current State:** Certain workflows lack top-level `permissions:` blocks or require review for dangerous triggers (e.g. `pull_request_target`).
- **Security Risk:** Workflows executed without strict permission boundaries can be exploited to modify repository state or leak credentials.
- **Target Fix:** Enforce top-level `permissions: contents: read` across all workflow files, restricting elevated permissions (`id-token: write`, `pull-requests: write`) exclusively to necessary jobs.

### 3.2 Output Sanitization & Safe Scripting (PIPE-002)

1. In `docker-publish-gcp.yml`, output writes use safe heredoc delimiter syntax:

   ```bash
   {
     echo "digest<<EOF"
     echo "$DIGEST"
     echo "EOF"
   } >> "$GITHUB_OUTPUT"
   ```

2. In `.github/workflows/actionlint.yml`, unverified script downloading is replaced by the pinned actionlint Action (`reviewdog/action-actionlint`) configured with `fail_level: error` and `filter_mode: nofilter` to strictly block CI on errors:

   ```yaml
   name: Actionlint

   on:
     push:
       branches: [main]
     pull_request:
       branches: [main]

   permissions:
     contents: read

   jobs:
     actionlint:
       runs-on: ubuntu-latest
       steps:
         - name: Checkout code
           uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1

         - name: Run actionlint
           uses: reviewdog/action-actionlint@d63ba7532e0942965320cd8d73cbae4c7b3c5283 # v1.73.1
           with:
             fail_level: error
             filter_mode: nofilter
   ```

### 3.3 Automated Security Scanning Workflow (PIPE-003)

The automated security scanning workflow (`.github/workflows/security-scan.yml`) runs four dedicated jobs on pushes and PRs to `main`, and on a weekly schedule:

```yaml
name: Security Scanning

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  schedule:
    - cron: "0 4 * * 1" # Weekly Monday scan

permissions:
  contents: read

jobs:
  gosec-scan:
    name: Go Security Scan (gosec)
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - name: Set up Go
        uses: actions/setup-go@b7ad1dad31e06c5925ef5d2fc7ad053ef454303e # v7.0.0
        with:
          go-version-file: "k8s-operator/go.mod"
          cache: true
          cache-dependency-path: "k8s-operator/go.sum"
      - name: Run gosec
        working-directory: k8s-operator
        run: go run github.com/securego/gosec/v2/cmd/gosec ./...

  trivy-scan:
    name: Container & Manifest Scan (trivy)
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - name: Scan Repository Configs & Manifests
        uses: aquasecurity/trivy-action@ed142fd0673e97e23eac54620cfb913e5ce36c25 # v0.36.0
        with:
          scan-type: "config"
          exit-code: "1"
          severity: "HIGH,CRITICAL"
          trivyignores: ".trivyignore.yaml"

  semgrep-scan:
    name: SAST Scan (semgrep)
    runs-on: ubuntu-latest
    container:
      image: semgrep/semgrep:1.155.0@sha256:cc869c685dcc0fe497c86258da9f205397d8108e56d21a86082ea4886e52784d
    steps:
      - name: Checkout code
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - name: Run semgrep
        run: semgrep ci --config=.github/semgrep-security-audit.yml --exclude=.github/semgrep-security-audit.yml --severity=ERROR

  checkov-scan:
    name: IaC Security Scan (checkov)
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - name: Run Checkov
        uses: bridgecrewio/checkov-action@69437f47399a9e321cd0f08938cb5cf2bb846dba # v12.2928.0
        with:
          framework: terraform,github_actions
          output_format: cli
          config_file: .checkov.yaml
```

### 3.5 Permissions Scoping & Event Trigger Security (PIPE-006)

- All workflow files set explicit top-level `permissions: contents: read`.
- Job-level `id-token: write` and `pull-requests: write` permissions are restricted exclusively to steps requiring GCP Workload Identity Federation or GitHub API comment/review creation.

## 4. Codebase Alignment & Security Governance

A comprehensive audit of the codebase (`.github/workflows/*`, `.github/dependabot.yml`, `Makefile`, and `k8s-operator/`) was conducted to evaluate potential conflicts and align the design with inline codebase comments. The following design decisions and governance rules are established as the reference of record:

1. **Event Triggers & Zizmor Ignore Annotation (`.github/workflows/auto_request_review.yml:4`):**
   In `.github/workflows/auto_request_review.yml`, there is an inline comment: `# zizmor: ignore[dangerous-triggers] - requesting a reviewer needs pull-requests: write, which pull_request cannot grant on fork PRs; no checkout, no other secrets`. The `# zizmor: ignore[dangerous-triggers]` annotation is retained as valid governance documentation for `pull_request_target` triggers. Using `pull_request_target` is required here to grant `pull-requests: write` for automated reviewer assignment on fork PRs without checking out untrusted code or exposing repository secrets.

2. **Gosec Security Scanner & `#nosec` Directives (`k8s-operator/`):**
   In `k8s-operator/internal/controller/platformagent_manifests.go:75` (`// #nosec G101 -- Policy JSON schema definition, not credentials`) and `k8s-operator/internal/testing/testutil/testutil.go` (`// #nosec G301`, `G304`, `G306`), existing code comments instruct Go security scanners (`gosec`) to ignore specific false-positive security rules, and file permissions for test fixtures are tightened (`0750` for directories, `0600` for files). The `gosec-scan` job in `.github/workflows/security-scan.yml` runs via the Go toolchain (`go run github.com/securego/gosec/v2/cmd/gosec ./...`) pinned in `k8s-operator/tools.go` and `go.mod`. It honors inline `#nosec` directives in the operator source code, blocking CI only when unannotated, genuine security vulnerabilities are introduced.

3. **Container Image & Local Ruleset Pinning (`security-scan.yml`):**
   Container images in CI workflows are pinned to explicit version tags and immutable SHA256 digests (e.g., `semgrep/semgrep:1.155.0@sha256:cc869c685dcc0fe497c86258da9f205397d8108e56d21a86082ea4886e52784d`) to guarantee deterministic execution and prevent upstream tag mutation. Semgrep rules are vendored locally in `.github/semgrep-security-audit.yml` and run with `--severity=ERROR` so that blocking CI behavior is restricted to high-confidence security findings, avoiding unexpected breaks from upstream ruleset changes.

4. **Checkov IaC Scans (`.checkov.yaml`):**
   In `.github/workflows/security-scan.yml`, Checkov is configured to scan Terraform and GitHub Actions files (`framework: terraform,github_actions`, `config_file: .checkov.yaml`). Non-production directories, benchmarks, and test fixtures are excluded via `.checkov.yaml` `skip-path` directives, allowing the scanner to operate in blocking mode for production manifests.

5. **Dependabot Ecosystem Coverage & Cooldowns:**
   In `.github/dependabot.yml`, dependency monitoring uses recursive glob patterns (`directories: ["/", "/**/*"]`) and a 7-day cooldown (`cooldown: default-days: 7`) across all ecosystems (`gomod`, `pip`, `npm`, `docker`, `github-actions`) to guarantee repository-wide dependency discovery and prevent day-0 dependency updates from introducing regressions.

6. **Static Scanner Ignores (`.trivyignore.yaml` and Zizmor Annotations):**
   During CI validation, Trivy flagged rule KSV-0118 on Kustomize overlay patch files in `k8s-operator/config/integrations/` where `securityContext` is intentionally omitted because it is merged into target deployments, KSV-0046 on sample read-only explorer ClusterRoles (`platform-agent-explorer`) using wildcard resource read permissions, KSV-0112 on sample read-only explorer Roles (`developer-team-agent-explorer`) using wildcard resource read permissions, and GCP-0061 / GCP-0048 on staging PoC / companion Terraform configurations (`k8s-operator/testing/staging_workloads/main.tf`, `terraform/**`). Similarly, Zizmor flagged Medium-severity `secrets-inherit` rules on reusable integration workflows (`staging-redeploy-integrations.yml`, `autopush-redeploy-integrations.yml`) and `dependabot-cooldown` warnings on `.github/dependabot.yml`. To prevent plain-text ignore rules from suppressing checks repository-wide on production targets, these rules are explicitly scoped using the YAML ignore format (`.trivyignore.yaml`), which applies `paths` selectors per rule (`KSV-0118`, `KSV-0046`, `KSV-0112`, `GCP-0061`, `GCP-0048`, `DS-0002`, `KSV-0014`, and `KSV-0050`). Additionally, Trivy rule DS-0029 flagged missing `--no-install-recommends` flags on `apt-get install` commands in `deploy/docker/Dockerfile`, which were resolved by adding `--no-install-recommends`, and rule DS-0002 was addressed on `deploy/docker/Dockerfile` by explicitly dropping to non-root `USER 10000:10000` at the end of both published stages (`platform` and `credential-proxy`).

## 6. Risk Assessment & Monitoring

- **Risk Assessment:** Low risk. Pinning actions to immutable commit SHAs increases reliability and prevents unexpected upstream breakage.
- **Monitoring:** Security scanning findings are monitored via the GitHub Security tab and Action run outputs.
